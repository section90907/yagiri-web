# 未来年表(/future/)の更新

年に1回、内容を見直して更新する(ページの注記にも、そう書いてある)。

## 仕組み
- 元データ(人が編集する): `content/future/timeline_public_v1.csv`
- 変換した、ページ用のデータ: `content/future/future-timeline.json`(217項目。確認中の項目は `pending: true`)
- ビルドが、ハイライト(これまで・2030・2035・2040・2050+・YAGIRI'S TAKE)を、HTML に直接出力する(検索に載せるため)。
- アーカイブ(全項目の絞り込み)は、ビルドが出す `/future/timeline.json` を、ブラウザが読んで描く。**確認中(pending)の項目は、このデータにも入れない。**
- 絞り込みの状態は、URLに入る(例 `/future/?cat=Y&kind=pred`)。共有できる。

## 更新の手順
1. `content/future/timeline_public_v1.csv` を編集する。文章は「公開見出し」「公開本文」「なぜこの年」の列。
   - 確認が取れた項目は、「公開区分」を `非表示(確認中)` → `アーカイブ` にする。
   - 目玉にする項目は、「ハイライト」列に `これまで / 2030 / 2035 / 2040 / 2050` を入れる。
2. `python3 scripts/csv_to_future_json.py content/future/timeline_public_v1.csv content/future/future-timeline.json`
3. `npm run build` が通ることを確認し、確認用で見てから公開する。最終更新日は、データから自動で入る。

## 守ること
- **文言は、醸造家の監修済み。勝手に要約・言い換えをしない**(YAGIRI'S TAKE は特に)。
- 出典のURLは、年に1回、リンク切れを確かめる。
- ハイライトに指定した項目が、確認中のままだと、ビルドが止まる(公開できない項目を、うっかり出さないため)。
- バッジは形で区別している(色だけに頼らない)。記録=塗り、予定・目標=実線の枠、予測=点線の枠、思索=ワインレッドの塗り。確度の●は「予定・目標」と「予測」だけに出す。

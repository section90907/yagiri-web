# メニュー作成スレッドへの指示文(タップリスト + サイトのデータ)

毎週のタップリスト(PDF)を作るスレッドに、次の指示文を渡す。サイトを担当するスレッドが、出力されたJSONを `content/taplist.json` に取り込む。
**「味の方向(likes)」の基準は、ここが正。** 別のスレッドや、次のセッションでも、この基準を使う。基準を変えるときは、この文書を直し、`content/taplist.json` の既存の銘柄も合わせて見直す。

関連: `docs/TAPLIST_UPDATE.md`(取り込みの手順)/ `src/partials/beer-finder.html`(診断の点数のつけ方)

---

あなたは、YAGIRIYA(矢切ブルワリーの直営タップルーム)のメニュー担当です。
毎週のタップリスト(PDF)を作る作業に、次の「出力」を足してください。
サイトを担当する別のスレッドが、あなたの出力をそのまま公式サイトに取り込みます。

## 目的
サイトの「ビール診断」(5つの質問で、いまのタップからおすすめを選ぶ機能)が、タップリストの
レーダーチャートの値と、「味の方向」を使います。レーダーは毎回あなたが作るので、
その元データを、サイトにも渡してください。

## 出力(毎週、PDFと一緒に)
1. タップリストのPDF(いつもどおり)
2. **taplist_YYYYMMDD.json**(下の形式。コードブロックで貼る。ファイルでも出せるなら出す)
3. 先週からの変更点(追加・終了した銘柄)
4. 「味の方向(likes)」で迷った銘柄の一覧(迷った理由を一行ずつ。人が確認します)

## 大事なルール
- **レーダーチャートは、JSONの数値から描く。** JSONを先に作り、その数値でチャートを描いてください。
  PDFの図とJSONの数値が、ずれてはいけません(同じ元データから作る)。
- 数値は **1〜5の整数** です。
- 推測で埋めないでください。分からない値があれば、空にして、最後の「迷った一覧」に書いてください
  (サイトは、profile のない銘柄を診断の対象から外します。外れるほうが、間違った勧め方より安全です)。

## JSONの形式(1銘柄 = 1ブロック)
```json
{
  "updated": "2026-10-21",
  "items": [
    {
      "no": 1,
      "name": "Saison de Blue",
      "ruby": "",
      "style": "セゾン",
      "original": true,
      "brewery": "",
      "abv": 6.6,
      "regular": 900,
      "big": 1400,
      "tag": "スパイシー",
      "desc": "(タップリストの説明文と同じ)",
      "profile": { "bitter": 2, "sweet": 1, "fruity": 3, "body": 2, "special": 4 },
      "likes": ["spicy"],
      "likesNote": "迷った場合だけ、理由を一行"
    }
  ],
  "sets": {
    "title": "飲み比べセット", "price": 1000, "size": "3種 × 各100mL",
    "items": [ { "title": "IPAセット", "desc": "…", "order": [5, 7, 6] } ],
    "note": "「→」はおすすめの飲む順番"
  }
}
```
- no: 番号(バドワイザーのような定番は null)。original: 自社の銘柄だけ true(その場合、brewery は空)
- ruby: 読み仮名や英字表記。無ければ空
- tag: レーダーの「銘柄ごとの軸」のラベル(スパイシー、ロースト、酸味、にごり、ドライ…)
- profile の意味(レーダーの軸と同じ):
  bitter=苦味 / sweet=甘味 / fruity=フルーティー / body=コク / special=銘柄ごとの軸(tag の強さ)

## 「味の方向 likes」の付け方(迷いにくいように、基準を決めます)
1銘柄に、1〜2個。強い順に並べてください。次の5種類から選びます。
- classic = すっきり王道。淡色ラガー系(ピルスナー、ヘレス、ラガー)。または、クセが少なく、
  bitter・fruity・body がすべて2以下で、のどごし・クリア・ドライ系のもの
- fruity = フルーティー・トロピカル。fruity が4以上、または、果実を使ったもの
- roasty = 香ばしい・黒ビール系。焙煎麦芽が主役(ブラック、シュバルツ、スタウト、ポーター、
  黒いもの)。tag が「ロースト」「香ばしさ」
- spicy = スパイス・ハーブ系。スパイスやハーブ、ボタニカルを使った、セゾン、ヴァイツェン系
  のスパイス感。tag が「スパイシー」「ハーバル」
- hoppy = ホップの香りと苦味(IPA系)。スタイル名に IPA を含む、または bitter が4以上
- 迷ったら、候補を2つ書いて(likes に入れる)、likesNote に理由を一行書いてください。
  3つ以上は付けません(診断の結果が、ぼやけます)。

## 出力前のチェック(あなたが確認してから出す)
- [ ] profile の5つの値が、すべて1〜5の整数
- [ ] PDFのレーダーの形が、JSONの数値と一致している
- [ ] 説明文と数値が食い違っていない(例: 説明に「苦みはほぼなし」とあるのに、bitter が3以上)
- [ ] likes は1〜2個、5種類のどれか
- [ ] sets の order の番号が、items の no と対応している
- [ ] abv が小数1桁、regular・big が整数の円
- [ ] JSONとして正しい(カンマや引用符の漏れがない)

# ビールのスペックとアーカイブ(PRODUCT)

PRODUCT を「買う場所」から「スペックと過去の記録を見る場所」に変えた(2026-10)。購入は引き続き BASE。

## 仕組み
- データは `content/beers.json` の `beers` 配列。**1銘柄=1件=1ページ**。版や仕込み回が違っても同じ銘柄は1つにまとめる。
- ファイルが無い・空のときは `/beer/` を出さない(PRODUCT のリンクはトップの該当欄に戻る)。
- ビルドで `/beer/`(一覧。販売中 → アーカイブの順)と `/beer/<slug>/`(詳細)を作る。
- 項目: `slug`(半角英小文字・数字・ハイフン。URLになるので決めたら変えない) / `name` / `ruby` / `style` / `status`(`current` か `retired`) / `abv` / `ibu` / `og` / `fg` / `hops[]` / `malts[]` / `adjuncts[]`(副原料。乳糖・ブドウ糖など。乳糖は乳成分なので必ず載せる) / `yeast[]` / `first`(初めて仕込んだ年) / `desc`(ひとこと) / `shop_url`(販売中のみ。省略するとショップのトップ) / `draft`(true だと確認用でだけ見える)。
- **無い項目は載せない**(0 として出さない)。`name` `style` `slug` `status` 以外は省略してよい。
- 数字は、レシピ(最新の版)の値。仕込みごとの実測値は載せない。

## 載せるもの・載せないもの(公開リポジトリなので)
- 載せる: ホップ名・モルト名・酵母名・ABV・IBU・OG/FG。
- **載せない**: 原料の使用量・配合の分量・原価・単価・投入のタイミング。レシピの再現につながる数字は出さない。

## 銘柄のまとめ方(BrewLedger のレシピの系列と対応づける)
- 版が違っても同じ銘柄は1つ。
- 名前の読み替え: `CANVASX2` → **CANVAS** / `SUNPARADEANNIN` → **SUNPARADE D.P.**
- **除外**: `PEETAIPA`(OEM のため載せない)。
- 載せるか迷う銘柄(試作・ボツ・共同醸造)は、載せる前にオーナーに確認する。

## 更新の手順
1. BrewLedger のレシピ(最新の版)から、上の項目だけを写す。
2. `content/beers.json` に追記。新規は `draft: true` で入れ、確認用で見てから外す。
3. `npm run build` と `npm run build:staging` が通ることを確認。
